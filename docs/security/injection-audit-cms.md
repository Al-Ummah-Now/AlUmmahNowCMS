# Injection Security Audit — AlUmmahNowCMS

Defensive injection audit covering input validation, SQL/D1 parameter binding, bknd query/operator filters, stored XSS & page-builder fields, media uploads & R2 key safety, SSRF in admin-configured AI providers, AI prompt/output boundaries, open redirects, CRLF/header injection, and log injection.

## Findings & Control Inventory

| --- | --- | --- | --- | --- |

| Media upload validation (`src/lib/paths.ts`, `src/index.ts`) | Multipart & raw uploads to `/api/media/upload*` and `/api/media/entity/*` | **High (CMS-4 — MIME spoofing / SVG & HTML polyglot):** Only `Content-Type` header and filename extension were checked; SVG/HTML disguised as `image/png` bypassed the SVG ban, and missing/NaN `Content-Length` bypassed the 10 MB cap on raw uploads. | **Fixed:** Added `sniffImageType()` magic-byte verification (JPEG, PNG, WebP, AVIF exact headers) matching declared MIME type on both multipart and raw uploads; verified actual byte length `<= MEDIA_MAX_BYTES` and rejected negative/NaN `Content-Length`. | `test/node/injection-audit.test.ts` (`CMS-4, CMS-5, CMS-6`), `test/worker/injection-audit.test.ts` (`CMS-4, CMS-5, CMS-6`) |

| Public media response headers (`src/routes/public-api.ts`, `src/lib/paths.ts`) | `GET /api/public/v1/media/*` `path` | **Medium (CMS-6 — Missing `Content-Disposition`):** Media served without a sanitized `Content-Disposition` header. | **Fixed:** Added `safeDispositionFilename()` and set `Content-Disposition: inline; filename="..."` for allowlisted image types (`attachment` for `application/octet-stream` fallback), alongside existing `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`. | `test/node/injection-audit.test.ts` (`CMS-4, CMS-5, CMS-6`), `test/worker/injection-audit.test.ts` (`CMS-4, CMS-5, CMS-6`) |
| bknd Data API query filters (`src/lib/bknd-query.ts`, `src/index.ts`, `src/lib/scholars/ownership.ts`) | `/api/data/entity/*` `where`, `sort`, `select`, `limit`, `offset`, `with`, `join`, and `/fn/count` body | **High (CMS-7 — Operator injection & relation join bypass):** `scopeWhere`/`scopeWhereStaff` only stripped top-level `$` keys; nested/unknown `$` operators, prototype pollution keys, dotted relation fields, `with`/`join` relation expansion, unvalidated `sort`/`select`/`limit`, and `?where=` query smuggling on `/fn/count` were not blocked. | **Fixed:** Added `validateBkndEntityRequest()`, `validateWhereObject()`, and `sanitizeScopedWhere()` allowing only safe leaf operators, blocking `$or`/`$and` for scoped roles, rejecting prototype keys, unknown `$` operators, `with`/`join`, and invalid `sort`/`select`/`limit`/`offset`; stripped query strings on `scope-count` rewrites. | `test/node/injection-audit.test.ts` (`CMS-7`), `test/worker/injection-audit.test.ts` (`CMS-7`) |
| AI assist prompts, glossary, & output validators (`src/lib/ai/prompts.ts`, `src/lib/slug-suggest.ts`, `src/lib/translation-flags/retranslate.ts`, `src/lib/translation-flags/glossary.ts`) | Draft content, titles, translation flags, glossary terms/notes, and model JSON outputs | **Medium (CMS-8 — Prompt injection breakout & HTML in model output):** Untrusted content could break out of `<document>`, `<title>`, `<source>`, `<translation>`, `<note>` delimiters; glossary entries were injected unescaped; AI outputs did not strip injected raw HTML tags or `javascript:` links. | **Fixed:** Added `escapePromptXml()` neutralizing closing tags in all prompt blocks; wrapped sanitized single-line glossary entries in `<glossary>` data tags; strengthened system prompt to forbid raw HTML/scripts/tool calls; hardened `validateSeo`, `validateCheck`, `validateTranslateChunk`, and `validAlternatives` to strip control chars, raw HTML tags, and dangerous Markdown link schemes. | `test/node/injection-audit.test.ts` (`CMS-8`) |
| Content validation rules (`src/lib/content-rules.ts`) | `pages`, `posts`, `nav_items`, `site_settings`, `curated_videos` writes | **Medium (CMS-9 — Missing length limits & control chars in URLs):** `validNavUrl`/`validHttpsUrl` allowed ASCII control chars stripped by `new URL()`; content fields lacked server-side max lengths and tag count/length caps. | **Fixed:** Rejected control chars in `validNavUrl`/`validHttpsUrl`/`validWebUrl`; enforced server-side max lengths on `title`, `slug`, `summary`, `excerpt`, `seo_title`, `seo_description`, `author_name`, `body`, `nav_items.label`, `curated_videos.title_override`, `site_settings` fields, and `posts.tags` (≤ 50 tags, ≤ 80 chars each). | `test/node/injection-audit.test.ts` (`CMS-9, CMS-10, CMS-12, CMS-14`) |
| Scholar post ref URLs (`src/lib/scholars/ref-public.ts`, `src/routes/public-api.ts`) | `PostSummaryV2` media URLs & `v2.link.url` | **Medium (CMS-10 — Unsafe URL schemes in public API):** `mediaOf()` accepted any string URL and `v2.link.url` was served without scheme validation. | **Fixed:** `mediaOf()` now requires `validHttpsUrl()`; `v2.link` requires `validWebUrl()` (`http:`/`https:` with no control chars). | `test/node/injection-audit.test.ts` (`CMS-9, CMS-10, CMS-12, CMS-14`), `test/worker/injection-audit.test.ts` (`CMS-10, CMS-11, CMS-13, CMS-14`) |
| Translation flag Qur'an links (`src/admin/translation-flags-api.ts`, `src/admin/client/translation-flags.ts`) | `flag.quran_url` / `f.quranUrl` | **Medium (CMS-11 — Unvalidated external link scheme):** `quran_url` was passed to client `<a href>` without validating `https://quran.com`. | **Fixed:** Enforced `^https://quran\.com(?:\/[^\s]*)?$` both server-side (`publicFlag`) and client-side (`translation-flags.ts`, rebuilt into `client.generated.ts`). | `test/worker/injection-audit.test.ts` (`CMS-10, CMS-11, CMS-13, CMS-14`) |
| Structured logging & error handlers (`src/lib/log.ts`, `src/index.ts`, `src/routes/public-api.ts`, `src/routes/picker.ts`, `src/routes/preview.ts`, `src/admin/api.ts`, `src/admin/lists-api.ts`, `src/admin/timeline-api.ts`, `src/lib/slug-suggest.ts`) | Error messages / external error strings logged to console | **Low/Medium (CMS-12 — Log injection):** `errText()` did not strip `\r\n`/control chars, and several routes logged raw strings via `console.error`/`console.warn`. | **Fixed:** Added `sanitizeLogText()` stripping `[\r\n\u0000-\u001f\u007f]` in `log.ts` and `errText()`, and replaced raw route `console.error`/`console.warn` calls with structured `log.error`/`log.warn`. | `test/node/injection-audit.test.ts` (`CMS-9, CMS-10, CMS-12, CMS-14`) |
| D1 SQL queries (`src/admin/lists-api.ts`, `src/admin/suggest-api.ts`, `src/lib/feed/source.ts`) | Tag search `q` (`LIKE`), `liteItems` `posts`/`entries` arrays | **Low/Medium (CMS-13 — SQL LIKE wildcard injection & array interpolation):** Tag search `LIKE` did not escape `%`, `_`, `\`; `liteItems` interpolated `sel.posts.map(Number).join(",")` directly into SQL instead of bound parameters. | **Fixed:** Escaped `%`, `_`, `\` with `ESCAPE '\'` in `lists-api.ts` and `suggest-api.ts`; replaced interpolation in `liteItems` with safe positive-integer filtering and `?` bound parameters. | `test/worker/injection-audit.test.ts` (`CMS-10, CMS-11, CMS-13, CMS-14`) |
